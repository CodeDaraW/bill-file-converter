# bill-file-converter

Bank statement PDF to CSV converter powered by local or BYOK VLM APIs.

This is the Go rewrite. The previous pure frontend implementation has been moved to `legacy/`.

## Current Scope

- v1 supports PDF input only. Email statements should be printed/exported as PDF first.
- Parsing uses rendered page images, not PDF text-layer extraction.
- The model outputs JSON first; CSV is generated by program logic from that JSON.
- CSV preserves the original statement table layout for a registered adapter. It does not normalize transactions across banks.
- Web UI is not implemented in v1. `web/` is a placeholder for future local-only UI work.

## CLI Setup

Build or run the CLI:

```bash
go run ./cmd/bill-file-converter list-types
go build ./cmd/bill-file-converter
```

Install a PDF renderer. The CLI currently supports:

- `pdftoppm` from poppler
- `mutool` from MuPDF

On macOS:

```bash
brew install poppler
```

Create a config file:

```bash
go run ./cmd/bill-file-converter config init -out config.json
```

Default config targets LM Studio's OpenAI-compatible endpoint:

```json
{
  "provider": {
    "provider": "openai-compatible",
    "base_url": "http://localhost:1234/v1",
    "api_key_env": "LLM_API_KEY",
    "model": "qwen/qwen3.5-vl-9b",
    "temperature": 0,
    "thinking_enabled": false
  },
  "renderer": {
    "command": "pdftoppm",
    "dpi": 200
  }
}
```

For LM Studio, start a local OpenAI-compatible server and set `api_key_env` to any env var if the server does not require a real key. For hosted providers, set `provider`, `base_url`, `model`, and `api_key_env` accordingly.

Supported provider values:

- `openai-compatible`: LM Studio, Ollama/OpenAI-compatible, OpenRouter, LiteLLM, Vercel AI Gateway, and similar gateways.
- `anthropic`
- `gemini`

Thinking/reasoning is disabled by default. To enable it for models/providers that support it, set:

```json
{
  "provider": {
    "thinking_enabled": true,
    "thinking_budget_tokens": 2048
  }
}
```

Provider support is best-effort:

- OpenAI-compatible: sends `reasoning_effort: "medium"` and, when a budget is set, a `thinking` object for compatible local/gateway APIs.
- Anthropic: sends native `thinking`.
- Gemini: sends `generationConfig.thinkingConfig`.

## CLI Usage

List supported statement types:

```bash
go run ./cmd/bill-file-converter list-types
```

Convert a PDF:

```bash
go run ./cmd/bill-file-converter convert ./statement.pdf \
  --type cmb_debit \
  --config config.json \
  --out output
```

Each conversion creates a fixed-length task id and writes all artifacts under `--out <task_id>/`, so repeated runs do not overwrite each other. The task id is formatted as date + time + a crypto-random suffix, for example `20260501-153045-a1b2c3d4`.

Outputs:

- `output/<task_id>/result.json`: source file info, local-time `generated_at`, metadata, extracted tables, validation report, artifact paths.
- `output/<task_id>/result.csv`: strict table CSV generated from JSON. It contains only table headers and data rows; title and other document-level information belong in `metadata`.
- `output/<task_id>/pages/*.png`: rendered PDF pages.

Inspect without producing CSV:

```bash
go run ./cmd/bill-file-converter inspect ./statement.pdf \
  --type cmb_debit \
  --config config.json \
  --out output-inspect \
  --debug
```

Validate provider config and renderer availability:

```bash
go run ./cmd/bill-file-converter providers test --config config.json
```

## Acceptance Checklist

Use this checklist for a new setup or a new adapter:

1. `go test ./...` passes.
2. `go run ./cmd/bill-file-converter list-types` shows the intended adapter key.
3. `go run ./cmd/bill-file-converter providers test --config config.json` succeeds.
4. `convert` writes both `result.json` and `result.csv`.
5. Logs include the task id, and artifacts are written under `output/<task_id>/`.
6. `result.json.task_id` matches the output directory name.
7. `result.json.source` records the source PDF path/name, and `generated_at` is present in the machine's local timezone.
8. `result.json.metadata` contains adapter-required metadata from the original PDF text.
9. Metadata keys use English `snake_case`, such as `account_no` and `verification_code`.
10. `result.json.tables[].headers` exactly matches one adapter-approved profile.
11. Empty visual cells are `null` in JSON and empty fields in CSV.
12. CSV column order and row order match the source PDF table layout, with no metadata/title rows.
13. If the expected table/header is not present, conversion fails validation instead of generating a guessed CSV.

## First Adapter: `cmb_debit`

The first concrete adapter is registered in `core/prompts.go` as `cmb_debit` for 招商银行借记卡交易流水.

It defines:

- Required metadata: `title`, `english_title`, `statement_period`, `name`, `account_no`, `account_type`, `sub_branch`, `application_time`, `verification_code`
- Expected table headers: either `记账日期`, `货币`, `交易金额`, `联机余额`, `交易摘要`, `对手信息`; or the same columns plus `客户摘要`
- A dedicated VLM prompt that asks the model to preserve original table layout and return JSON only
- A CSV profile that writes table content only, without metadata or title rows

Add a new bank adapter by following the same pattern:

1. Add a new adapter constructor in `core/prompts.go`, for example `bocCreditAdapter()`.
2. Give it a stable key, readable name, required metadata keys, exact expected headers, and adapter-specific prompt text.
3. Register it in `builtinAdapters()` only after the prompt/profile is specific enough to reject unsupported formats safely.
4. Add golden tests with page-image fixtures and fake VLM JSON for that adapter.
5. Run `go test ./...` and a real `convert` against a desensitized PDF before considering it supported.

Unregistered statement types are intentionally unsupported.
